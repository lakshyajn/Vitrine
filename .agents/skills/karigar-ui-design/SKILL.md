# Karigar UI design skill

Use for layouts, visual concepts, responsive behavior, reusable components and polish.
1. Read `docs/DESIGN_SYSTEM.md`, `docs/WS1_FRONTEND_CONTEXT.md` and relevant contract/decision files.
2. State the user's goal, information hierarchy, primary action and key states before coding.
3. Make an evidence-led trade workspace, not a generic AI dashboard. Use deliberate type/spacing and restrained color; use imagery only with purpose.
4. Keep category/country generic outside the demo scenario.
5. Distinguish verified evidence, AI assessment, unknowns, demo data and taste/market hypotheses.
6. Never invent metrics, retailers, logos, citations, URLs or claims. Avoid decorative charts and generic AI slogans.
7. Design loading, empty, error, disabled and pending states. Explain desktop/tablet/mobile behavior.
8. Use semantic HTML, keyboard support and visible focus.
9. Implement one screen at a time; inspect it in a running browser before expanding.
